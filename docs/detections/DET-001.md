# DET-001 — PowerShell launched with an encoded command, or a hidden window plus a download cradle

> Status: **fixture-validated** (2026-08-29). Compiled query proven on a live Elasticsearch 8.19.20
> against synthetic fixtures. Not yet run against telemetry generated on a real host.

## Objective

Answer "is PowerShell being used to stage or hide a payload on this host?" without alerting on the
thousands of ordinary PowerShell launches a fleet produces. Two shapes are targeted: an encoded
command (the operator does not want the command line readable), or a hidden window combined with a
download cradle (the operator wants the payload fetched without a visible console).

## ATT&CK mapping

- Technique: T1059.001 — Command and Scripting Interpreter: PowerShell
- Authoritative URL: <https://attack.mitre.org/techniques/T1059/001/>
- Version/access date: Enterprise ATT&CK v19.2, accessed 2026-08-29
- Mapping rationale: the rule keys on the interpreter's own launch flags, which is the technique's
  procedure level, not on the payload that follows.

## Data requirements

- Sensor and configuration: Sysmon EventID 1 (process creation) shipped through the Elastic
  Windows/Sysmon integration; `process.executable` and `process.command_line` populated.
- Event IDs/categories: Sysmon 1 (`winlog.channel: Microsoft-Windows-Sysmon/Operational`,
  `event.code: 1`).
- Required fields: `process.executable` (matched through the `.caseless` subfield the Elastic
  pipeline targets), `process.command_line`.
- Known collection gaps: Security 4688 without command-line auditing has no command line at all;
  PowerShell started through a COM host or `pwsh` on a non-Windows host is outside this logsource.

## Detection logic

1. The image is `powershell.exe` or `pwsh.exe`, **and**
2. either the command line carries one of the encoded-command switches (`-e`, `-ec`, `-en`, `-enc…`;
   PowerShell accepts any unambiguous prefix of `-EncodedCommand`, and Atomic tests 15–17 rotate
   through them), **or**
3. the command line carries a hidden-window switch (`-w hidden`, `-window hidden`,
   `-windowstyle hidden`) **and** a download cradle token (`Net.WebClient`, `DownloadString(`,
   `DownloadFile(`, `Invoke-WebRequest`, `IEX `, `IEX(`).

The hidden-window clause alone is not enough: scheduled maintenance scripts routinely run hidden.
Pairing it with a cradle is what separates staging from housekeeping.

## False positives and tuning

Researched (from the rule's `falsepositives` and vendor documentation):

- RMM agents and Intune remediation scripts that intentionally run encoded commands. Tune by
  parent process and signer, not by weakening the command-line match.
- Administrators pasting encoded one-liners from vendor documentation.

Observed: none — this rule has not been run against production telemetry.

## Triage guidance

1. Decode the `-enc` payload (UTF-16LE base64) and read it before anything else; the content decides
   the severity.
2. Pull the parent process and its command line; `explorer.exe` or an Office binary as parent is a
   different conversation from `svchost.exe -k netsvcs -p -s Schedule`.
3. Check whether the host reached the cradle URL (proxy/DNS logs) and whether the same command line
   appears on other hosts in the last 24 h.

## Blind spots

- **Case sensitivity is a deployment property, not a rule property.** Sigma `contains` is
  case-insensitive; the compiled Lucene query is only case-insensitive if the index field is
  lowercase-normalised. The lab mapping (`lab/index-mapping.json`) normalises `process.command_line`;
  the stock Elastic Windows integration maps it as `wildcard` (case-sensitive), and the pySigma
  `ecs_windows` pipeline does not redirect `CommandLine` to the `.caseless` subfield the way it
  does for `Image`. `test_case_variants_depend_on_the_index_mapping` proves both outcomes: the
  uppercase `-ENC` fixture hits on the lab mapping and misses on the stock one.
- Encoded commands passed through `-Command` with a `[Convert]::FromBase64String` call are not
  caught; that is the `Invoke-Expression`-on-decoded-text variant and belongs to a script-block
  logging rule (PowerShell 4104), which needs a different logsource.
- `-w hidden` without a cradle (payload already on disk) is deliberately silent.

## Hunt note

- Hypothesis: encoded PowerShell on workstations is rare enough to review by hand.
- Query: DET-001 without the cradle clause, grouped by parent executable, last 7 days.
- Benign noise expected: RMM agents, Intune, a few admins' shell aliases — each with a stable parent.
- Signal: an encoded command whose parent is a browser, an Office binary, or `wscript.exe`.
- Follow-up: turn any stable benign parent into a documented filter with a change record.
