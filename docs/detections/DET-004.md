# DET-004 — Run-key persistence pointing at a user-writable path or script host

> Status: **fixture-validated** (2026-08-29). Compiled query proven on a live Elasticsearch 8.19.20
> against synthetic fixtures. Not yet run against telemetry generated on a real host.
> CrowdStrike LogScale: **not compiled** — the pySigma Falcon pipeline has no `registry_set`
> mapping (`detections/compiled/manifest.json`).

## Objective

Flag Run / RunOnce / Policies\Explorer\Run values whose data points somewhere a standard user can
write, or that launch a script host. Legitimate software registers tray agents under Program Files;
malware registers itself under the profile. The rule encodes that difference and accepts the
documented cost (per-user apps that install under AppData).

## ATT&CK mapping

- Technique: T1547.001 — Boot or Logon Autostart Execution: Registry Run Keys / Startup Folder
- Authoritative URL: <https://attack.mitre.org/techniques/T1547/001/>
- Version/access date: Enterprise ATT&CK v19.2, accessed 2026-08-29
- Mapping rationale: covers the registry half of the technique only; Startup-folder drops are file
  writes (Sysmon 11) and need a separate rule.

## Data requirements

- Sensor and configuration: Sysmon EventID 13 (registry value set) with a configuration that
  includes `CurrentVersion\Run` targets, shipped through the Elastic Windows/Sysmon integration.
  The fixture assumes `TargetObject` is retained in `winlog.event_data` and mirrored to
  `registry.path`, and `Details` is retained alongside `registry.data.strings`.
- Event IDs/categories: Sysmon 13 (`event.code: 13`).
- Required fields: `registry.path`, `winlog.event_data.Details`.
- Known collection gaps: a Sysmon configuration that excludes HKU Run keys sees nothing; values set
  through offline hive edits or `secedit` (Atomic test 16) are not observed as EventID 13.

## Detection logic

1. `registry.path` contains `\Software\Microsoft\Windows\CurrentVersion\Run\`, `…\RunOnce\`, or
   `…\Policies\Explorer\Run\`, **and**
2. the value data contains a user-writable path (`\AppData\`, `\Temp\`, `\Users\Public\`), a script
   host or shell (`powershell`, `pwsh`, `cmd /c`, `mshta`, `wscript`, `cscript`, `rundll32`,
   `regsvr32`), or a script extension (`.vbs`, `.js`, `.bat`, `.ps1`, `.hta`).

Both clauses are required: negative control 2 places an AppData path under a non-Run key and stays
silent; negative control 1 places a Program Files binary under Run and stays silent.

## Validation

- Positive fixture: `FIX-DET-004-POS` — 3 events (HKCU Run → AppData executable, HKCU RunOnce →
  PowerShell download cradle, HKLM Run → `wscript.exe` with a `.vbs` under `Users\Public`). Shapes
  follow Atomic Red Team T1547.001 tests 1 and 3. Note: test 1's default `command_to_execute` is
  `C:\Path\AtomicRedTeam.exe`, which this rule would **not** flag; the fixture models the test with its
  input argument set to an AppData path, and that choice is recorded in `meta.yml`.
- Negative control: `FIX-DET-004-NEG` — 3 events (vendor tray agent under Program Files, AppData
  path under `Explorer\Shell Folders`, Windows setup's own RunOnce cleanup).
- Source telemetry fixture: `tests/fixtures/telemetry/DET-004/`.
- SIEM alert evidence: `test_query_returns_exactly_its_own_positives[DET-004]` — 3 of 3 positives,
  0 of 15 negatives.
- Query/backend translation: `detections/compiled/elastic/DET-004.lucene`. LogScale: unsupported,
  reason recorded in the manifest; a hand-written Falcon `AsepValueUpdate` query is future work.

## False positives and tuning

Researched:

- Per-user applications that install under `AppData\Local` (some chat clients, updaters) register
  Run values there. Allowlist by value name and signer after review; do not drop the AppData clause.
- Enterprise logon scripts pushed through `Policies\Explorer\Run` — allowlist the GPO-managed
  value names.

Observed: none — no production telemetry has been run through this rule.

## Triage guidance

1. Read the value data and resolve the target file: does it exist, who wrote it, is it signed?
2. Check the writing process (`process.executable` on the same event): `reg.exe` from a user shell,
   `powershell.exe`, or an installer.
3. Look for the same value name across hosts; commodity malware reuses names.

## Blind spots

- Startup-folder persistence (Atomic tests 4–7), Winlogon `Userinit`/`Shell` (14–15), and
  `BootExecute` (17) are different keys or file writes and are out of scope here.
- A payload staged under `C:\ProgramData\` or a vendor-looking path under Program Files that the
  attacker can write to is not caught; the rule trades that for silence on legitimate installers.
- `registry.path` casing (`SOFTWARE` vs `Software`) is handled by the lab's lowercase-normalised
  keyword mapping; on the stock mapping this becomes case-sensitive (DET-001, Blind spots).

## Hunt note

- Hypothesis: Run values are stable per host; new value *names* in the last 7 days are reviewable.
- Query: Sysmon 13 on Run/RunOnce keys, grouped by value name, first-seen in the window.
- Benign noise expected: OneDrive, Teams, vendor updaters, with stable names and signed targets.
- Signal: random-looking names, targets under `Users\Public` or `Temp`, script hosts.
- Follow-up: feed confirmed benign names into a documented filter list with a change record.
