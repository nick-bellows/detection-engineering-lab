# DET-002 — LSASS memory dump via comsvcs MiniDump or ProcDump

> Status: **fixture-validated** (2026-08-29). Compiled query proven on a live Elasticsearch 8.19.20
> against synthetic fixtures. Not yet run against telemetry generated on a real host.

## Objective

Catch the two ways of writing `lsass.exe` memory to disk that need no custom tooling: the
`MiniDump` export of `comsvcs.dll` through `rundll32`, and Sysinternals ProcDump aimed at lsass.
Both leave an unambiguous command line, which makes this a high-confidence, low-volume rule.

## ATT&CK mapping

- Technique: T1003.001 — OS Credential Dumping: LSASS Memory
- Authoritative URL: <https://attack.mitre.org/techniques/T1003/001/>
- Version/access date: Enterprise ATT&CK v19.2, accessed 2026-08-29
- Mapping rationale: the procedures are named in the technique description; the rule detects the
  procedure, not the outcome (the dump file).

## Data requirements

- Sensor and configuration: Sysmon EventID 1 through the Elastic Windows/Sysmon integration.
- Event IDs/categories: Sysmon 1 (`event.code: 1`, Sysmon operational channel).
- Required fields: `process.executable`, `process.command_line`.
- Known collection gaps: direct-syscall dumpers (Dumpert, NanoDump) and Task Manager's "Create dump
  file" produce no such command line; they need Sysmon EventID 10 (process access to lsass with
  `0x1010`/`0x1fffff` granted access), which is the follow-on rule listed in `docs/future-work.md`.

## Detection logic

Either

1. the image is `rundll32.exe` and the command line contains both `comsvcs` and `MiniDump`, or
2. the image is `procdump.exe`/`procdump64.exe`, the command line has a `-ma` or `-mm` switch,
   and it names `lsass`.

The comsvcs branch requires both tokens: `comsvcs.dll` is loaded by rundll32 for other exports
(negative control 3 uses `Sysdiag`). The ProcDump branch requires the lsass target: dumping any
other process is ordinary debugging (negative control 1).

## False positives and tuning

Researched:

- Administrators dumping *other* processes with ProcDump — excluded by the lsass target.
- Crash-reporting tools that load comsvcs.dll — they do not pass `MiniDump` on a rundll32 command
  line.
- Endpoint products that legitimately read lsass do so through process access, not these command
  lines. Dumping lsass on purpose is rare enough that every hit should become a ticket.

Observed: none — no production telemetry has been run through this rule.

## Triage guidance

1. Confirm the dump file path from the command line exists (or existed) and who owns it; a
  successful dump means credentials should be considered exposed on that host.
2. Identify the parent chain: an interactive admin shell versus a service or an Office child.
3. Look for follow-on activity within minutes: new outbound connections, `pass-the-hash` style
   logons (4624 LogonType 9 / NTLM from that host), archive tools touching the dump.

## Blind spots

- Direct-syscall and API-unhooking dumpers (Atomic tests 3, 4, 14), Task Manager (test 5), and
  Mimikatz operating in memory (test 6, 10) create no matching command line.
- Renamed ProcDump binaries defeat the `Image|endswith` clause; `OriginalFileName` (Sysmon
  `OriginalFileName: procdump`) would close that gap and is a one-line change once the fixture set
  models it.
- The same case-sensitivity caveat as DET-001 applies to `MiniDump` and `lsass` on the stock
  Elastic mapping.

## Hunt note

- Hypothesis: any process opening lsass with `0x1fffff` access outside the EDR/AV allowlist is
  worth a look, regardless of command line.
- Query: Sysmon 10 where `TargetImage` ends with `\lsass.exe`, grouped by `SourceImage`, 30 days.
- Benign noise expected: the endpoint agent, `csrss.exe`, `wininit.exe`, some backup agents.
- Signal: anything under a user profile path, or a signed-but-unexpected binary such as
  `rdrleakdiag.exe` or `createdump.exe`.
- Follow-up: promote the stable allowlist into the EventID 10 rule in future-work.
