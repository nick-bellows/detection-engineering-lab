# DET-003 — Scheduled task created to run as SYSTEM or from a user-writable path or script host

> Status: **fixture-validated** (2026-08-29). Compiled query proven on a live Elasticsearch 8.19.20
> against synthetic fixtures. Not yet run against telemetry generated on a real host.

## Objective

Separate the scheduled tasks attackers create for persistence and privilege escalation from the
ones installers create every day. The dividing line used here is *what the task runs and as whom*:
SYSTEM context, or an action living in a user-writable directory or delegating to a script host.

## ATT&CK mapping

- Technique: T1053.005 — Scheduled Task/Job: Scheduled Task
- Authoritative URL: <https://attack.mitre.org/techniques/T1053/005/>
- Version/access date: Enterprise ATT&CK v19.2, accessed 2026-08-29
- Mapping rationale: the rule watches the `schtasks.exe` creation procedure named in the technique;
  it does not cover tasks created through the COM API, which the technique also describes.

## Data requirements

- Sensor and configuration: Sysmon EventID 1 through the Elastic Windows/Sysmon integration.
- Event IDs/categories: Sysmon 1.
- Required fields: `process.executable`, `process.command_line`.
- Known collection gaps: `Register-ScheduledTask`, `Invoke-CimMethod PS_ScheduledTask` and the Task
  Scheduler COM API never spawn `schtasks.exe`. Security 4698 ("scheduled task created") with the
  task XML is the logsource for those and is not collected in this lab.

## Detection logic

1. The image is `schtasks.exe`, **and**
2. the command line contains `/create`, **and**
3. either it runs as SYSTEM (`/ru system`, `/ru "nt authority\system"` variants), **or** the action
   points at `\AppData\`, `\Temp\`, `\Users\Public\`, or a script host / shell (`powershell`, `pwsh`,
   `cmd /c`, `mshta`, `wscript`, `cscript`, `rundll32`, `regsvr32`).

`/query`, `/delete` and `/change` are silent by construction (negative controls 2 and 3).

## Validation

- Positive fixture: `FIX-DET-003-POS` — 3 events (`/ru system` with a `cmd.exe /c` action, an
  AppData action, and Atomic test 2's `/Create /SC ONCE` capitalisation with a `powershell.exe` action
  under `Users\Public`). Shapes follow Atomic Red Team T1053.005 tests 1 and 2.
- Negative control: `FIX-DET-003-NEG` — 3 events (an MSI installer registering a Program Files
  updater task without `/ru`, a `/query`, a `/delete`).
- Source telemetry fixture: `tests/fixtures/telemetry/DET-003/`.
- SIEM alert evidence: `test_query_returns_exactly_its_own_positives[DET-003]` — 3 of 3 positives,
  0 of 15 negatives.
- Query/backend translation: `detections/compiled/elastic/DET-003.lucene`,
  `detections/compiled/crowdstrike-logscale/DET-003.cql` (compiled, not executed).

## False positives and tuning

Researched:

- Installers and update agents that register SYSTEM tasks (negative control 1 models the common
  case that stays silent; `/ru system` variants will fire). Allowlist by parent process and task
  name rather than removing the SYSTEM clause.
- Deployment scripts creating PowerShell maintenance tasks — the `powershell` token will fire.
  Expect this to be the main tuning surface in a real fleet.

Observed: none — no production telemetry has been run through this rule.

## Triage guidance

1. Read the `/tr` action and `/sc` trigger; a `cmd.exe /c` action pointing at a user profile path
   at logon is persistence, a vendor updater at 03:00 is not.
2. Check the parent: `msiexec.exe` or a vendor installer versus `cmd.exe` under an interactive
   session.
3. Confirm the task still exists (`schtasks /query /tn`) and export its XML; compare the author and
   principal with the command line.

## Blind spots

- Capitalisation: positive 3 (`/Create`) hits on the lab mapping only; on the stock Elastic
  mapping the compiled query is case-sensitive (see DET-001, Blind spots).
- Tasks created without `schtasks.exe` (see Data requirements).
- Actions that hide behind an indirection (`conhost.exe --headless`, LOLBins not in the list) are
  not enumerated; the list is deliberately short and documented rather than exhaustive.

## Hunt note

- Hypothesis: tasks whose action lives outside `Program Files`/`Windows` are unusual per host.
- Query: DET-003's action clause only (drop the `/create` requirement) over Security 4698 task XML,
  if collected; otherwise `schtasks /query /fo csv /v` exported per host.
- Benign noise expected: per-user updaters (browsers, chat clients) under `AppData\Local`.
- Signal: `cmd /c`, `mshta`, `wscript` actions, or a task name mimicking a Microsoft one.
- Follow-up: the per-user updater set becomes an explicit filter with a change record.
